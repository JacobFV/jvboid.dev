SynthUX is a low-compute synthetic data system for generating behavior-specific training records — and a Blender-first cinematic pipeline that applies the same discipline to video.

![SynthUX behavior program pipeline](/assets/img/projects/synthux-pipeline.svg)

The basic unit on the data side is not an instruction or a click trace. It is a sampled behavior program that renders a multi-paragraph spec, generates supporting artifacts, executes a symbolic UX trajectory across mock tools, and attaches routing labels plus score rubrics for small expert models.

## What It Generates

- Long-form behavioral instructions and specs.
- Artifacts such as design docs, code modules, tests, PR text, incident timelines, runbooks, source tables, and research memos — varied per task family rather than identical templates, and **causally coupled**: the PR cites the actual code module's exported symbol, the test imports that symbol's module, the Slack handoff references the file by path.
- Symbolic computer-use trajectories across Notion, Slack, GitHub, Editor, Terminal, Browser, and dashboards, emitted by walking the sampled behavior tree against a shared **EpisodeState** (workspace, threads, branches, terminal history, notion pages, dashboard panels). Each emitter reads and writes that state; the final state is serialized into `latent.final_state` so downstream training and evaluation can inspect what an episode actually accomplished.
- **Per-domain emitter overrides**: ops episodes dashboard-first with `drill_into_alert`, post a hypothesis-vs-mitigation split to `#incident`, and create an Incident Doc page. Research episodes start at arxiv, extract source quotes, and build a Source Triage with hypothesis-then-evidence structure. SWE keeps the generic emitters. The trace is domain-coherent, not the SWE if-ladder dressed in different clothes.
- Observations that vary per (surface, action, args) instead of constant strings, with timestamps that scale with the actual cost of each action (typing length, command class).
- Real failure-and-recovery branches when the latent declares ambiguity: pytest-fail → edit → pytest-pass, Slack clarification, or assumption-of-record patterns.
- **Archetype-based conditional sampling**: each domain declares coherent (organization, repository, role, goal, expert, task_family) tuples. Sampling picks an archetype first so episodes never end up with a "staff engineer" working on a "Svelte browser-desktop simulator" for an "open-source maintainer group" while filing a bug fix PR.
- **Constraint predicates**: each declared constraint maps to a structural predicate over (latent, artifacts, trajectory). "Include a rollback note and failure mode analysis" actually checks for those strings; "avoid risky production writes" rejects `DROP TABLE` in action args; "make the behavior easy to verify from a CLI" requires a terminal action. Score includes `constraints_satisfied` and `constraints_checked`.
- Export routing metadata for specialized fine-tunes (includes the `archetype_id` so downstream filters can route by it).
- Content-aware quality scores: `causal_coupling` measures how many trajectory actions target real artifact paths; `constraint_grounding` measures token overlap with declared constraints; `observation_uniqueness`, `ambiguity_resolved`, `expected_min_quality`.

## Why It Exists

Small routed experts need dense examples around a behavior domain. Full VM data collection is expensive, slow, and hard to inspect. Prompt-only synthetic data is cheap but usually loses the connection between task, artifacts, actions, and outcomes.

SynthUX sits between those approaches. Domain packs define statistical priors over task families, roles, goals, constraints, tools, artifacts, and trajectory policies. The generator samples from those priors and uses shared latent state so the instruction, artifacts, actions, routing labels, and scores agree.

## Initial Domains

- **SWE:** specs, implementation artifacts (per-task module variants — bugfix gets `reproduce_failure`+`patched`, refactor gets `migrate`, review gets `apply_review_notes`), tests that match, PRs with per-episode branch names, and mock Notion/Slack/GitHub/Editor/Terminal workflows.
- **Ops:** incident response, dashboards, Slack coordination, runbook updates, and postmortems.
- **Research:** literature triage, source notes, synthesis memos, and browser/document workflows.

## Bigger Picture

This is the same principle as executable node trees, but lifted above the UI level. A tree can describe a software project, a team workflow, a research process, or eventually a world-simulator episode. The UX trace is one rendering of the behavior program, not the whole program.

That makes on-demand data generation possible: choose a narrow behavioral domain, sample many coherent episodes cheaply, route them to the right expert model, and fine-tune or evaluate without waiting on human demonstrations or heavyweight virtual machines.

## Cinematic Generation: Blender Is The Substrate

![Cinematic authority taxonomy](/assets/img/projects/synthux-cinematic-authority.svg)

The same programmatic discipline applies to video, with a strict hierarchy: **Blender creates physically coherent reality, diffusion finishes that reality photographically, and Remotion assembles the edit.** Remotion is the finishing table, not the aesthetic substrate.

The core object is the **shot**: authority source, register, subject, lens, camera rig, motion curve, material emphasis, lighting state, proof object, render passes, narration alignment, transition logic, and forbidden cliches. A `cinematic/shots/*.json` file is the contract; everything downstream — Blender scene, render passes, diffusion job spec, Remotion timeline — is generated from it.

The Blender layer is real, not a scaffold. `python cinematic/scripts/generate_scene.py` emits a Blender 4.x renderer that:

- builds a per-shot proof object with PBR material slots derived from `shot.materials`, with emissive accent geometry for any material declaring emission;
- builds a three-light rig (large area key, narrow rim, soft fill) coloured from keyword analysis of the lighting block;
- configures a world background tuned per register;
- aims the camera via look-at math so the framing works in `--background` mode where TRACK_TO constraints don't get re-evaluated;
- animates the camera according to `motion.curve` (linear, ease-in-out, slow-dolly, macro-orbit, locked-off);
- writes beauty PNGs plus depth (EXR), normal (PNG), and mask (PNG) passes when declared.

The Remotion layer is intentionally ~25 lines: it loads the beauty PNG sequence with a 14-frame fade in/out and that's it. **No floating HUDs, no register/authority chips, no proof-object headlines, no narration subtitles, no frame counters.** A static lint at `cinematic/scripts/lint_remotion.mjs` refuses to ship Shot.tsx variants that re-introduce any of those patterns. Taste is encoded as type safety.

The 32-second vertical slice above is seven shots forming an industrial-design-film arc, each shot borrowing authority from a different register:

1. **Revelation** (luxury-product-cinema / aesthetic) — macro reveal of an etched logic core, seven emissive amber nodes carved into the face under a cyan rim.
2. **Material-Proof** (engineering-demonstration / operational) — extreme macro on a single etched trace; material specificity as proof.
3. **Instrumentation** (interface-choreography / operational) — top-down workbench of mock-tool panels with emissive accent strips lighting up in cause-and-effect order.
4. **Trajectory-Evidence** (documentary-proof / evidentiary) — a single editor-buffer slab populated with emissive code lines, modified indicator lit.
5. **Routing-Lock-In** (academic-research-film / scientific) — translucent dataset slabs sliding along parallel engraved rails into expert lanes with paper rubric tabs.
6. **Consequence** (manifesto / civilizational) — an expert-model glyph (sphere-on-cylinder, brushed-titanium with amber core) absorbing dataset slabs.
7. **Naming** (luxury-product-cinema / aesthetic) — a brushed-titanium nameplate with `SYNTHUX` engraved as a real 3D text object extruded into the metal. Diegetic typography per the cinematic-pipeline contract.

Each shot is built from a `subjectArchetype` in the JSON spec; the Blender layer dispatches to a per-archetype mesh builder. The seven narration lines, read in sequence, form the linguistic register of the film: declarative, materially grounded, impersonal — closer to a luxury watch launch than to a SaaS announcement. The full arc and per-shot rationale lives in [`cinematic/storyboard.md`](https://github.com/JacobFV/synthux/blob/main/cinematic/storyboard.md).
