RRP (it began as *relational robot policy*; the repository is now
`structured-psi0-latent-diffusion-dynamics`) asks what a robot policy should say
about its intentions if it is meant to survive a change of body. The answer it
tests is a **latent packet**: a planner emits a continuous tensor
$z\in\mathbb{R}^{K\times M\times D}$, one slot per knot time and per body assembly,
and a fast controller on the body turns the *received* packet into joint targets
using only what that body senses. Task meaning has to live on $z$, and the project
requires evidence for that from probes *and* from causal edits of the packet.

![The attention logit, one term at a time: each panel stretches one relational term for a single query token over a real simulator state. Values are computed by the factor operators, not learned attention.](/assets/img/projects/rrp-attention-logit.webp)

## Problem

A policy trained on one arm usually knows nothing useful about the next one. The
interface between "what should happen" and "how this body makes it happen" is
implicit, buried in weights, and it does not carry over. On top of that, most of
the structure a roboticist knows in advance — which joint is whose parent, what is
touching what, which object the task is about, which widget a label belongs to — is
left for the network to rediscover from data, if it does at all.

## Solution

Two ideas, kept separate so each can be tested on its own.

**The packet interface.** Following the $\Psi_0$ naming, System 1 is an
encoder–decoder transformer trained by rectified flow: it reads typed context
(morphology, scene, task events and roles, touch) and samples $z$ in 8 Euler steps.
System 0 runs every control tick: one query per actuated joint, built from public
morphology and the current measured state, cross-attends to the packet's knots and
outputs a normalized joint target. System 0 never sees the task, the instruction or
an image — the only way meaning reaches the body is through $z$. Packet queries are
computed from public morphology rather than looked up per robot ID, which is what
lets a new body produce new queries.

**Relational attention as a sum of declared terms.** Every attention call in the
model has the same logit:

$$
A_{ij}=\frac{q_i^{\top}k_j}{\sqrt d}+\sum_{f}w_{f,h}\,\gamma_f\,v_f(i,j)+\big\langle\phi_q(i),\phi_k(j)\big\rangle
$$

Each factor $f$ is one entry in a single registry — field × operator × form × source
— and contributes one term: an additive bias, a kernel-compatible augmentation
appended to $q,k$ (so fused attention kernels still apply), a task-conditioned gate,
or a hard mask. Relative geometry follows PaPE; graph terms come from declared
morphology and the supplied task graph; pair terms that can't be read from public
inputs (contact, support, held-by, handover) are bilinear, so the bias *is* a
supervised attention subspace and its probe estimate can be used at run time. Every
coefficient is zero-initialized, so switching a factor on in a trained model is a
no-op at step 0. A deploy guard refuses any simulator-truth source at run time:
ground truth trains the probes, and only public or estimated values steer attention.

## How

- **Language / runtime:** Python 3.12, PyTorch, one `rrp` CLI; every heavy job runs
  under a resource broker on two NVIDIA GB10 machines.
- **Simulation:** native MuJoCo with MuJoCo Menagerie robots, a batched Warp legged
  environment, the $\Psi_0$ SIMPLE benchmark on Isaac Sim, and
  [Computerworld](/projects/computerworld) rendered as a 3D UI world for a pointer
  track. 251 distinct embodiments have been simulated in at least one recorded run;
  150 of them are in a training set.
- **Code and weights:** the code is on
  [GitHub](https://github.com/JacobFV/structured-psi0-latent-diffusion-dynamics);
  checkpoints are on [Hugging Face](https://huggingface.co/jacob-valdez/rrp-checkpoints).
- **One interface each** for environments, policies and tasks; one harness runs any
  accepted policy × environment × task and records declined pairs with reasons.
- **Relation-aware data.** One privileged state interface feeds four registries —
  label functions, composable scene parts, factor-agnostic transforms (reveal,
  surprise, counterfactual swap, noise, occlusion, subsampling) and a composition
  operator — and a progressive-composition scheduler promotes each factor from
  isolated scenes to composed ones as its competence rises. The scheduler is
  implemented and smoke-tested; there is no curriculum result yet.

## Tests

The repository's merge gate is a unit suite (`pytest tests/unit`) that skips, by
name, anything needing weights or third-party assets. Evaluation uses matched seeds
across routes — R0 scripted teacher (privileged), R1 oracle packet (diagnostic, not
deployable), R2 generated packet (deployable) — plus a behaviour-cloning control on
the same demonstrations, and edit suites that change the task context and roll out.
Semantic and no-semantic variants are capacity-matched. Splits are sealed and
hash-pinned before results, and each sealed cell runs once.

## Results

Recorded results only, from the report's snapshot of 2 October 2026. All of it is
simulation; no physical robot was commanded.

- **Semantic supervision helps inside the training bodies.** On four arm bodies and
  two seeds, the latent route with semantic packet supervision succeeds in 425/480
  deployable episodes against 314/480 for the capacity-matched control: **+0.23
  [0.18, 0.28]**, ahead in 8/8 body × seed cells. The latent route is still below
  plain BC on Panda (135/180 against 58/60).
- **The packet is causally used.** A "halt" added to System 1's task context — which
  can only reach the body through $z$ — cuts forward progress by 0.40 m on anymal_c
  and 0.66 m on go2 relative to the control, 3/3 seeds ordered, while an irrelevant
  context change moves the body at most 0.02 m. In Computerworld a probe-guided packet
  edit pulls the pointer from 163 px to 41 and 22 px of the new target, against
  102–105 px for a random edit of equal norm. The edits are partial and task success
  is unchanged.
- **Transfer to a new arm is not supported.** Zero-shot on sealed xarm7 targets, the
  latent route and BC both score 0/200. With target demonstrations, BC fine-tuning
  reaches 69–192/200; the latent route's best adaptation (added after the sealed
  result, so post-hoc) beats a System 0 refit in 12/12 cells but stays below BC in
  12/12. The latent route has not beaten BC on any new body.
- **Pointer:** in-distribution, BC 398/400, semantic latent 372, control 368. On
  unseen words and names every learned method scores 0/100 — none copies characters
  from the instruction.
- **Pretrained humanoid ($\Psi_0$):** released 20/20, direct fine-tune 19/20, structured
  head 0/20 — traced to an integration fault (System 0 ignored the packet), not
  evidence against structure. The packet-use gate added afterwards passed; the
  closed-loop rerun is queued.

What the report does *not* claim: that the relation factors help (the experiment
that tests this is running), that the latent route transfers across bodies, or
anything about a real robot. A ten-node pre-registered campaign — humanoids, arm
diversity, $\Psi_0$, the pointer and the relation factors — is in progress, with its
gates written down before the runs.

## Lessons

The most useful thing in the repository turned out to be bookkeeping. An early
"semantic supervision hurts" result was a confound — an unbounded probe loss shrank
System 0's updates by two orders of magnitude — and it was only caught because every
comparison carries a decision number and a capacity-matched control. Labelling
every source (teacher, oracle, learned) on every frame and every table, and keeping
negative results in the same ledger as positive ones, cost little and kept the
project honest about where the latent route is still behind plain BC.

## Every factor, one tile each

All 75 implemented relation factors, grouped by family. Each tile draws one term of
the attention logit for a single query token (the ring) over a real simulator state,
with the scene's source in the corner. The values are computed by the factor
operators — they are not learned attention — and where a pair term is trained from
simulator truth, the tile shows the label that trains its probe, not the deployed
estimate. Three tiles are marked illustrative. Click any tile to enlarge it.
